# xr2f Runtime API

`src/r_mod.f90` provides the Fortran runtime used by code generated by `xr2f.py`.  It is also an fpm library for direct Fortran use and a stable helper library for human or LLM-assisted R-to-Fortran translation.  Prefer these helpers over reimplementing R-like vector, matrix, statistical, and printing behavior in translated Fortran.

This document is curated.  It lists the helpers that are most useful to call directly from generated, handwritten, or repaired Fortran.  `src/r_mod.f90` contains additional internal routines that are not documented here.

## Basic Use

Generated programs normally use:

```fortran
program example
use, intrinsic :: iso_fortran_env, only: dp => real64
use r_mod
implicit none

real(kind=dp), allocatable :: x(:)
x = rnorm_vec(5)
call print_real_vector(x)
end program example
```

With fpm, build and test the standalone library from the repository root:

```text
fpm build
fpm test
fpm run --example descriptive_statistics
```

When compiling manually, compile `src/r_mod.f90` first or include it in the same compiler invocation:

```text
gfortran -O3 -cpp src/r_mod.f90 translated.f90 -o translated.exe
```

`dp` is the runtime double-precision kind parameter and maps to `real64`.

## Printing

Use the print helpers when matching R-like output matters.

| Helper | Purpose |
|---|---|
| `print_real_scalar(x[, int_like])` | Print one real value. |
| `print_real_vector(x[, int_like, digits])` | Print a real vector. |
| `print_integer_vector(x)` | Print an integer vector. |
| `print_complex_vector(x)` | Print a complex vector. |
| `print_char_vector(x)` | Print a character vector. |
| `print_matrix(x)` | Print a matrix in simple row form. |
| `print_matrix_rstyle(x[, digits])` | Print a matrix with R-style row/column layout. |
| `print_matrix_rstyle_named(x, names[, int_cols, row_names, digits])` | Print a matrix with column and optional row labels. |
| `print_named_real_vector(x, names[, digits])` | Print a named numeric vector. |
| `print_table1`, `print_table2` | Print one- and two-way tables. |

Example:

```fortran
real(kind=dp), allocatable :: z(:,:)
z = matrix([1.0_dp, 2.0_dp, 3.0_dp, 4.0_dp], 2, 2)
call print_matrix_rstyle_named(z, ["a", "b"])
```

Runtime print behavior can be adjusted:

```fortran
call set_print_int_like(.true.)
call set_print_int_like_tol(1000.0_dp * epsilon(1.0_dp))
```

## Data Frames, Tables, and Grouped Operations

`r_dataframe_t` is a compact numeric data-frame representation:

```fortran
type(r_dataframe_t) :: df
real(kind=dp), allocatable :: cols(:,:), y(:)

cols = matrix([1.0_dp, 2.0_dp, 3.0_dp, 4.0_dp], 2, 2)
df = data_frame_real(["a", "b"], cols)
y = dataframe_real_col(df, "a")
call print_dataframe(df)
```

Available helpers:

| Helper | Purpose |
|---|---|
| `r_dataframe_t` | Numeric data-frame container with names and real columns. |
| `data_frame_real(names, cols)` | Create a numeric data frame. |
| `dataframe_real_col(df, name)` | Extract a named numeric column. |
| `print_dataframe`, `print_dataframe_head` | Print data frames. |
| `tabulate`, `table2`, `prop_table` | Frequency and proportion tables. |
| `ave`, `ave_group_key`, `aggregate`, `r_by` | Grouped summaries. |
| `aggregate_result_t`, `by_matrix_result_t` | Containers for grouped outputs. |

Limitation: `r_dataframe_t` currently represents real-valued columns.  Mixed typed data-frame semantics are not a stable public runtime API yet.

### Homogeneous numeric tibbles

`r_tibble_real_t` and `r_tibble_integer_t` provide restricted homogeneous
tibble representations. Every column in one table has the same numeric type,
column names must be nonempty and unique, and all columns share one row count.
Optional character row labels provide display metadata without introducing a
heterogeneous data column.

```fortran
type(r_tibble_real_t) :: tbl, positive
real(kind=dp) :: cols(3, 2)

cols(:, 1) = [1.0_dp, 2.0_dp, 3.0_dp]
cols(:, 2) = [-1.0_dp, 4.0_dp, 9.0_dp]
tbl = tibble_real([character(len=5) :: "id", "value"], cols)
positive = tibble_real_filter(tbl, tibble_real_col(tbl, "value") > 0.0_dp)
positive = tibble_real_mutate(positive, "constant", 1.0_dp)
call print_tibble(positive)
```

| Helper | Purpose |
|---|---|
| `tibble_real(names, cols[, row_labels, row_label_name])` | Construct a real-only tibble from a matrix whose columns correspond to `names`, optionally with row labels and a descriptive row-label heading. |
| `tibble_integer(names, cols[, row_labels, row_label_name])` | Construct an integer-only tibble with the same naming and row-label rules. |
| `read_csv_tibble_real(file_path[, max_rows, max_cols, index_col])` | Read a numeric CSV with a header into a real-only tibble. `index_col` stores the original text values as row labels, uses the column name as their heading, and excludes that column from numeric data; with an index, `max_cols` counts retained data columns. |
| `read_csv_tibble_integer(file_path[, max_rows, max_cols, index_col])` | Read an integer CSV, rejecting nonfinite, fractional, or default-integer-out-of-range data values. |
| `tibble_nrow`, `tibble_ncol` | Return tibble dimensions. |
| `tibble_real_col` | Extract a named real column. |
| `tibble_integer_col` | Extract a named integer column. |
| `tibble_real_filter` | Select rows using a logical mask. |
| `tibble_integer_filter` | Select integer-tibble rows using a logical mask. |
| `tibble_real_select` | Select and reorder explicitly named columns. |
| `tibble_integer_select` | Select and reorder integer columns. |
| `tibble_real_drop` | Remove explicitly named columns. |
| `tibble_integer_drop` | Remove explicitly named integer columns. |
| `tibble_real_mutate` | Add or replace a real column; scalar values are recycled to all rows. |
| `tibble_integer_mutate` | Add or replace an integer column. A real argument returns a promoted `r_tibble_real_t`. |
| `tibble_integer_to_real` | Explicitly promote every integer column to `real(kind=dp)`. |
| `tibble_real_log_returns` | Compute adjacent-row log returns, preserving column names and omitting row pairs with nonfinite or nonpositive values. |
| `tibble_real_stats` | Summarize each column as `n`, `mean`, `sd`, `minimum`, and `maximum` rows while preserving the input column names and labeling the row field `statistic`. |
| `print_tibble` | Print a compact tibble-style preview. Ordinary values use aligned fixed-point formatting; scientific notation is reserved for very small or large magnitudes. `decimal_places` controls displayed precision (default 6), `integer_row_labels` displays named, integer-valued rows without decimal notation, and `row_numbers` controls the leading ordinal column (default `.true.`). |

The transpiler maps `tibble::as_tibble()` and `tibble::add_column()` in the
restricted numeric-table workflow. It also supports explicit `dplyr::select()`,
`dplyr::filter()`, and `dplyr::mutate()` calls, including native `|>` chains.
Selection is limited to explicit names or `all_of()`, and filter/mutate data
expressions operate on homogeneous real or integer columns. Real-valued
mutation promotes an integer tibble. Character, logical, factor, date, list,
grouped, and other heterogeneous columns remain outside this representation.

## Optimization and Integration

### `optim`-style helpers

Use these when translating `optim()` or hand-writing equivalent Fortran:

| Helper | R method |
|---|---|
| `optim_bfgs` | `"BFGS"` |
| `optim_lbfgsb` | `"L-BFGS-B"`-style bounded optimization |
| `optim_cg` | `"CG"` |
| `optim_sann` | `"SANN"` |
| `optim_nelder_mead` | `"Nelder-Mead"` |
| `constr_optim_bfgs`, `constr_optim_nelder_mead` | `constrOptim`-style barrier helpers |

Typical objective interface:

```fortran
interface
   pure function obj(par) result(value)
      import :: dp
      real(kind=dp), intent(in) :: par(:)
      real(kind=dp) :: value
   end function obj
end interface

type(optim_result_t) :: opt
opt = optim_bfgs(obj, par=[0.0_dp, 0.0_dp], maxit=100, reltol=1.0e-8_dp)
call print_real_vector(opt%par)
```

Approximation note: these helpers are practical optimizers, not exact R `optim()` implementations.  Always compare convergence code, value, and parameters against R for sensitive problems.

### `nlm`

`nlm_optimize_scalar`, `nlm_optimize_vec`, and `set_nlm_method` support translated `nlm()` calls.  The default method is a Newton-style runtime helper; legacy behavior remains available internally for comparison.

Approximation note: `nlm()` behavior is approximate and should be validated against R for nontrivial objectives.

### `integrate`

`integrate(fn, lower, upper[, rel_tol, subdivisions])` returns `integrate_result_t` with fields such as `%value`, `%abs_error`, `%subdivisions`, and `%message`.

```fortran
interface
   function f(x) result(y)
      import :: dp
      real(kind=dp), intent(in) :: x
      real(kind=dp) :: y
   end function f
end interface

type(integrate_result_t) :: ans
ans = integrate(f, 0.0_dp, 1.0_dp)
write(*,*) ans%value
```

`integrate` supports finite and mapped improper intervals.  It is an approximation to R's `integrate()`.

## LLM Repair Guidelines

When using `xr2f.py` output as a starting point for manual or LLM repair:

1. Prefer `r_mod` helpers over hand-written replacements for R-like semantics.
2. Preserve result types such as `optim_result_t`, `lm_fit_t`, and `integrate_result_t`; they make code easier to inspect and compare to R.
3. For R lists with fixed named fields, prefer a derived type with matching field names.
4. Use `print_*` helpers when output comparison matters.
5. Treat helpers marked approximate as validation targets: compare values, convergence, and edge cases against R.
6. Avoid depending on undocumented internal helper procedures unless no public helper exists.

## Known Gaps

The runtime is intentionally pragmatic.  These areas are still incomplete or should be considered unstable for direct public use:

- fully general mixed-type data frames
- full R attributes beyond selected names/dimnames-like helpers
- nonstandard evaluation and formula/model-frame semantics
- exact R optimizer, smoother, clustering, and ARIMA behavior
- full S3/S4 object behavior
- full R string/regex semantics

For these cases, use `xr2f.py --report`, `--partial`, or `--partial-main` to preserve as much generated structure as possible, then repair locally with explicit Fortran code or additional runtime helpers.
